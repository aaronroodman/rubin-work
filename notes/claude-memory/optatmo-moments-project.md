Rebuilding the old PIFF `optatmo3` idea as a standalone system in
`rubin-work/optatmo/`: fit a Double-Zernike optical wavefront +
constant atmospheric kernel to stellar HSM moments, and compare the fitted DZ
to the CWFS donut-wavefront retrieval (the 2016 Roodman & Davis comparison).

Status (as of 2026-07-09):
- Phase 1 (accuracy study of the SPIE-2026 analytic moment method): done — analytic geometric moments OK for 2nd order, but 3rd/4th are diffraction-dominated (trefoil skew 100% diffractive) → need Fraunhofer. See FINDINGS.md.
- Phase 2: JAX `Fraunhofer × atmosphere × HSM-adaptive-moment` forward model (`jax_optatmo.py`, `jax_hsm.py`), validated vs galsim/PIFF to <1%, autodiff exact.
- Phase 3 (data): target night dayObs **20260513** (only May FAM-triplet night, best seeing 0.71"); sample in-focus visits seq **31** (rotator≈59°) and **34** (rotator≈−1°). Our recomputed moments validated against RubinTV (FWHM/e/kurtosis percentiles match to ~0.002–0.01).

Key conventions decided with the user:
- **Annular** Noll Zernikes, Batoid LSST pupil: D=8.36 m, obscuration **0.612**.
- Fit in the **OCS** (telescope) frame: rotate measured CCS moments→OCS by rotator angle, per spin (e=spin2→2θ, coma spin1→θ, trefoil spin3→3θ); model is OCS-native. MIW reconstructed OCS+rotated-CCS with spin phase ([[aos-dof-terminology]]).
- Replace raw-DZ + parameter-SVD fitting with **AOS sensitivity-matrix v-Modes** (`ofc_svd.build_ofc_svd`): fit 12 v-Mode amplitudes + atmosphere r0,L0,g1,g2. See [[aos-22dof-reduced-set]] and [[aos-vmode-normalization]].
- Fraunhofer currently regular jnp.fft (16× oversample+rebin); Matrix DFT (Soummer 2007) is a planned faster backend.
- Jitter/wind-shake = constant moment offset, but dropped (degenerate with atm shear g1,g2).

**2026-08-10 coordinate-frame resolution (the big fix):** THREE camera-related frames, verified against the intrinsicZernikes calib footprints.
- **DVCS** = what `cameraGeom` FIELD_ANGLE returns `(field_x,field_y)`; also the frame of pixel-stamp HSM moments and RubinTV mosaics. Camera-fixed.
- **CCS** = camera frame used by the MIW calib + `aggregateAOSVisitTableRaw`; DVCS with a pure **x↔y swap** (`thx_CCS = field_y`). (User's def: CCS moves with the camera rotator.)
- **OCS** = mirror/telescope frame, constant in Alt/Az; `OCS = R(rotTelPos)·CCS`.
- Bug found & fixed: optatmo's star positions AND moments were DVCS but were rotated to "OCS" WITHOUT the swap → whole dataset was a reflection of true OCS → good moment fit but reflected wavefront, poor CWFS-corner correlation. Fix = `frames.dvcs_to_ccs_field` (swap) + `frames.dvcs_to_ccs_moments` (e1→−e1, M21↔M12, M30↔−M03, M31→−M31, M04→−M04) applied to positions+moments BEFORE the rotator rotation, in `data_fit.load_and_prep` and `consdb_cwfs` corner positions. `miw.zernikes` takes OCS positions, rotates back R(−sign·rot)→CCS for per-det interp; data `SIGN` must equal `MIWCalib.rotation_sign` (both default +1) — verified self-consistent for refits. No re-extraction needed (parquets store raw DVCS).
- **RubinTV Az/El frame** (El on y, Az on x) = PURE rotation of DVCS by the rotator (NO swap), pinned from the RubinTV rosette: at rot≈0 `Az=+field_y, El=−field_x`; general `Az=field_y cosρ−field_x sinρ, El=−field_y sinρ−field_x cosρ` (rotation by −(90°+ρ)). Differs from the fit's OCS by the CCS reflection (OCS is the mirror image). Validation plot: `optatmo/code/plot_whiskers_frames.py` (DVCS|OCS|Az/El, with rosette). NB: cannot pin a rotation sign by matching whiskers across exposures — optics+atmosphere differ too much; use the rosette.
- **CWFS corners now from ConsDB** (`consdb_cwfs.py`, reuses `aos_trim.make_consdb_client` + `aos_state.fetch_corner_zernikes_consdb`): `cdb_lsstcam.ccdvisit1_quicklook` z4..z28, rotator from `visit1_quicklook.physical_rotator_angle`. **Validated 20260513 seq25: ConsDB corner Zernikes share the danish/OCS frame+sign, corners map correctly** (R00/R04/R44 Z4 agree ≲0.03µm; R40 0.16µm gap explained by older-danish/different-donut-selection, not a frame issue). Use `--validate` to compare vs `cwfs_<visit>_danish.parquet`.
- `consdb_cwfs.py` uses `make_consdb_client(url='auto')` so it runs on the RSP (in-pod `consdb-pq.consdb`) AND on S3DF sdfiana/slacrd batch (external `usdf-rsp.slac.stanford.edu/consdb` + token from `~/.lsst/consdb_token`). `in_rsp()` keys off `/etc/nublado`.
- Current run mode: **50/34 DOF/v-mode**, official MIW baseline, free fit to 2nd/3rd/4th-order moments; jmax=26 (AOS Z4–Z26 omit Z20,Z21).

**2026-08-13 refactor (fit_optatmo + campaign layout + cleanup):**
- **`run_vmode_fit.py` DELETED → `code/fit_optatmo.py`** is THE fit driver (argparse, not token=). A fit is a **PLAN** = ordered STAGES; each stage frees a v-mode subset and WARM-STARTS from the previous stage's optimum. Presets: `full` (all v-modes+atm), `focus` (v1+atm), `focus_then_full` (v1+atm → free all). Flags: `--day --seqs --campaign(req) --plan --init(cwfs) --minimizer(lbfgsb|migrad) --skip-existing --svd --coll --filt --reg/--regmode/...`. Writes ONE **multi-stage npz** per visit (per-stage A/atm/model_mom/cost/chi2 + combined mon trace + stage_evals).
- **iminuit MIGRAD** (`--minimizer migrad`, `run_migrad`): needs **jax float64** — `fit_optatmo` sets `jax.config.update('jax_enable_x64', True)` at import. Without it MIGRAD stalls (float32 gives ~1e-3 abs precision at cost~1e4; L-BFGS-B tolerated it). lo==hi bounds → fixed MIGRAD params.
- **Tikhonov DROPPED by default** (config `regularization.lambda: 0`): 20260513 λ-scans showed it only raised moment cost, no knee, ~no correlation gain. Capability kept (`--reg`, wavefront/hinge forms) but off.
- **Output layout** (`code/campaign.py`): `output/runs/<campaign>/<day>/{fits,reports,ensemble}` + `manifest.json` + `config_snapshot.yaml`; **explicit `--campaign` label**. Shared inputs stay in `data/` (psfmoments/cwfs/visitmeta) with the SVD now at **`data/svd/`**. Filenames are simple (`vmodefit_<seq>.npz`, `fit_<seq>.pdf`) — no more `_cwfs_v1_...` tag soup.
- `plot_data_model.py` / `ensemble_vmodes.py` / `ensemble_corners.py`: all argparse `--campaign --day [--seqs] [--stage last|all|N]`. `ensemble_vmodes` = fitted-A vs CWFS-A_init per v-mode + atmo-FWHM vs donut-blur (Butler-free). `ensemble_corners` = per-Noll PSF-vs-CWFS deviation (needs Butler/MIW).
- **Orchestration = option 1** (no Snakemake; old `pipelines/Snakefile` deleted): `pipelines/fit_array.sbatch` (per-task, env CAMPAIGN/PLAN/INIT/MINIMIZER/CWFS_SRC/SKIP) + `pipelines/run_campaign.sh CAMPAIGN PLAN MINIMIZER DAY "SEQS" [CWFS_SRC]` (pre-extract → fit array → afterok ensemble job).
- **Result so far (stage1 v1-only + stage2 full, 20260513):** only **v1≈Z4/focus** correlates PSF-fit vs CWFS (r≈0.6); higher v-modes near-noise. Stage 2 tests whether freeing all modes finds a better CWFS-correlating minimum; MIGRAD tests the minimizer. Target night still **20260706**.
- **Pruned 14 orphaned scripts** (Phase-1/2 experiments + old drivers). Active model deps kept: `jax_optatmo` (JaxOptAtmoPSF, MOMENT_LABELS), `dz`, `moments_hsm`, `model`, `fit`, `vmode_fit`, `data_fit`, `frames`, `miw`, `config`, `fit_monitor`.
- **Ensemble = one script**: `ensemble_corners.py` (deleted `ensemble_vmodes.py`) does corner-Zj scatter + per-v-mode fitted-vs-CWFS grid + atmo-FWHM-vs-donut-blur, all with a **robust Huber fit (free intercept)** and slope/intercept/r **summary bars**; outputs `_fits.csv` (per-term slope/intercept/r) + `_visits.csv` (per-visit v-mode amps + fwhm + blur). `--all-days` pools every night of a campaign. Shared helpers in `ensemble_util.py`. Result 20260513: only **Z4 (v1/focus)** correlates PSF-vs-CWFS, slope ~0.66; higher terms near noise. MIGRAD == scipy but slower → **use scipy (lbfgsb)**; MIGRAD needs `m.strategy=0` + jax x64.
